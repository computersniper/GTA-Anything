# GTA 模组工程实践与排错经验沉淀 (Clean-Room Engineering Playbook)

本文档提炼了在 GTA V（特别是 **GTA V Enhanced / Gen9** 与 **Legacy / Gen8** 并行生态）中进行复杂模拟玩法构建与排错的可迁移工程准则，是 `GTA-Anything` 架构设计的直接现实依据。

---

## 1. 版本与加载链认知准则

1. **双构建号分别记录**：
   - 游戏磁盘可执行文件版本号（FileVersion，例如 `1.0.1158.16`）与底层 Hook 工具内部识别枚举（例如 Script Hook V 日志中的 `VER_EN_1_0_1158_13`）往往存在小版本映射别名差异。预检与诊断日志中必须**同时记录两者**。
2. **区分两条独立加载链**：
   - **RPH (RAGE Plugin Hook) 链**：从 `plugins/` 加载（典型代表如执法模拟体系），拥有独立控制台、协程调度与崩溃捕获机制。
   - **ASI / SHVDN 链**：ASI Loader 从根目录加载 `.asi`（如 `ScriptHookV.dll`、`OpenRPF.asi`、`ScriptHookVDotNet.asi`），再从 `scripts/` 加载 `.NET` 脚本（`SHVDN v2`、`SHVDN v3`、`SHVDN Enhanced`）及 UI 库（`LemonUI`、`NativeUI`）。
   - 两条链的启动顺序、按键钩子、日志位置与失败阶段完全不同；互不兼容或按键重叠的重型玩法配置应采用**可逆多套 Profile 隔离切换**，而非强行混装在同一运行目录。

---

## 2. 玩法机制与资产解耦准则

1. **区分「单步任务动作」与「完整运营闭环」**：
   - 以城市公共交通为例，简单的「把乘客从 A 拉到 B」不等于「线路运营模拟」。真正的玩法转译必须涵盖：选线与时刻/票价配置 → 车辆整备出车 → 站序推进与进站停靠 → 车门控制与乘客上下车 → 完班结算与场站收车。
2. **菜单选配与实体生成解耦**：
   - 在菜单滚动浏览（`OnIndexChange`）时同步生成 3D 预览车辆是经典反模式：一旦模型尚未流式就绪或内存吃紧，`CreateVehicle` 返回空句柄，紧随其后的属性调用（如 `RemoveAllExtras`）会立即抛出 `NullReferenceException`。
   - **标准做法**：菜单阶段仅展示静态文本卡片或 2D 贴图预览；用户确认开班后再进入独立的流式加载与出车状态。
3. **原版基线先行 (Vanilla-First Baseline)**：
   - 先用纯脚本 + GTA 原版内置车辆/NPC 跑通完整运营闭环，验证脚本逻辑无误后，再挂载独立 Add-on 车辆 DLC (`dlc.rpf`)，从而精准隔离「脚本缺陷」、「资产兼容缺陷」与「加载器缺陷」。

## 3. Gen8 / Gen9 资产兼容与五道门禁

GTA V Enhanced 使用 **Gen9** 资产管线，而历史社区大量资产面向 **Legacy (Gen8)** 构建。新增独立载具资产必须依次通过五个独立验证点：

| 门禁 | 验证内容 | 常见故障点与 Gen9 特别注意事项 |
| :--- | :--- | :--- |
| **Gate 1: 静态二进制解析** | 检查 `.yft` / `.ytd` 版本与内部纹理格式 | 经工具转换后的 Gen9 载具常见目标版本为 `.yft = 171`、`.ytd = 5`。**特别警惕 `script_rt_*`（如 `script_rt_dials_race` 仪表盘渲染目标贴图）**：若仍保留 Gen8 常见的 `DXT1` 格式会导致 Gen9 异常退出，需改为单 mip 的 `B8G8R8A8_UNORM`。 |
| **Gate 2: DLC 注册挂载** | `dlc.rpf` 打包与 `dlclist.xml` 登记 | 通过 `mods/` 独立副本路径加载，严禁直接覆盖原版归档文件；保留文件哈希与撤回清单。 |
| **Gate 3: 模型流式载入** | `RequestModel` 轮询与超时保护 | 车型名已在 `dlclist.xml` 登记仍可能载入超时；**超时后必须调用释放请求 (`MarkAsNoLongerNeeded`)** 并平滑回退至原版兜底车型。 |
| **Gate 4: 世界实体生成** | `CreateVehicle` 非空校验与地面放置 | 校验返回句柄非空且 `Exists()` 为真后再操作部件、涂装或镜头。 |
| **Gate 5: 业务交互闭环** | 玩家入座、车门开关、NPC 寻路上下车 | 校验座位索引、车门骨骼以及 AI 任务在目标车型上可正常完成。 |

## 4. 环境预检与七层验收证据链

1. **环境干扰前置排除**：
   - 大体积 `.rpf` 副本（动辄数 GB）极易挤满系统盘；系统虚拟内存/可提交内存余量不足（如低于 1 GB）会引发进程在运行中途无弹窗退出或图形分配错误。每次测试前必须记录盘符余量与系统可提交内存余量，避免将系统资源枯竭误判为脚本逻辑 Bug。
2. **七层验收证据阶梯 (7-Layer Acceptance Ladder)**：
   - **L1** 配置与资产静态可读 → **L2** 加载器成功识别 → **L3** 脚本初始化成功 → **L4** 菜单可唤起操作且无抢键 → **L5** 任务/班次可正式启动 → **L6** 核心业务循环完整跑通 → **L7** 退出或中止时实体与句柄干净释放。
